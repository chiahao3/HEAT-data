Verdict

The algorithm and the recorded results check out; the archive does not yet launch as documented. Every number the paper quotes is reproduced from the bundled logs, with one unit slip in the H-sublattice text. The EAT-modified FAIRChem patch behaves as the method requires on the real UMA model. The WSe2 objective, its rescored losses and the Fig. 4c correlations reproduce to ~10−7. New searches run with production settings on our cluster once two small launch bugs are worked around.

Fresh searches with the real model on our cluster: HEAT H reached its reference at generation 2 (23,826 evals, gap -1.1e-04 eV/atom); conventional H has not reached its reference after 21 generations (best gap 0.0117 eV/atom, 93,851 evals); the HEAT edge rerun ran out of GPU memory on a 20 GB MIG slice in its first crossover generation, hung instead of failing (issue below), and is queued again on a full A100; a reduced HEAT WSe2 run (population 10, otherwise production settings) went from 0.125 to 0.061 in 2 generations, in line with the archive's 0.109 → 0.057 at population 50; the conventional WSe2 driver, with its YAML fixed, completed 2 generation(s) (best loss 0.1420; archive at the same point: 0.1490). A full HEAT WSe2 search takes about five GPU-days in the archive, so we did not rerun it; it is covered by rescoring and the recorded metrics instead.

01 · What the repository is

Code, inputs and recorded runs for three structure searches

HEAT embeds Effective Atom Theory (EAT) in a genetic algorithm. Each site is a mixture of real species and a null species; positions and mixture weights relax together under a UMA interatomic potential, a Tsallis entropy term (“syntropization”) drives sites to a single species or to null, and the result is rounded and relaxed as ordinary atoms before scoring. Crossover halves both parents’ occupancies (κ = 0.5), superimposes them in the shared cell, prunes overlaps and re-relaxes, so atoms from either parent can survive or vanish. The baseline is a conventional hard-atom GA with cut-and-splice crossover and mutations.

The archive holds the HEAT drivers (3.2k–12k lines each), the conventional GAs, a launcher (run_search.py) with portable configs, the inputs (Mg(BH4)2 CIF, NIST Fe dislocation dumps, the experimental WSe2 phase volume), the recorded logs/metrics of every run in the paper, plotting scripts, and the FAIRChem patch that implements effective atoms. Model weights and per-generation structure exports are not included.

04 · WSe2 structure

HEAT recovers two Se–W–Se trilayers and the twist angle

The paper says the best HEAT structure “resolves the six atomic planes of two twisted Se–W–Se trilayers”. We tested that geometrically on the bundled 280×280 crops, against the independently registered guided reference. Heights are clustered into six planes; a W counts as trilayer-coordinated when it has exactly three Se 1.2–2.2 Å above and three below within 2.9 Å.

Structure (central crop)Atoms (W / Se)Planes (W / Se pure?)W with 3+3 SeW–Se bond (median)Twist between W layers

Pearson correlation of z-summed projections over the 280×280 display crop: 0.9344 (HEAT) and 0.1241 (conventional) from the bundled TIFFs, 0.9331 and 0.1233 when we re-render from the bundled cropped structures with the production renderer. The experimental crop is reproduced bit-for-bit from the raw TIFF. In both HEAT and the guided reference, adjacent W layers are 7.5–8.0 Å apart, against about 6.5 Å in 2H-WSe2. The layer thickness and W–Se bond length are bulk-like, so the larger spacing likely comes from the experimental depth scale and the 4 Å depth response. The paper does not discuss it.

05 · Effective-atom implementation

The FAIRChem patch does what EAT needs

The archive ships the effective-atom implementation as a patch against FAIRChem cce3699. It applies cleanly. We tested its defining properties on the real uma-s-1p1 model and on FAIRChem’s own random-weight UMA-architecture test checkpoint.

PropertyTestReal UMAStatus

On the random-weight test checkpoint, a null site did shift the energy by 0.01–0.08 eV. That model caps neighbors at 20, and its untrained normalizer is not zero. On the production model (cap 300) the shift disappears. A null site can still occupy one of the 300 neighbor slots when a region is very dense in effective sites; a 6 Å sphere would need more than 0.33 sites/Å3. We did not observe this, but it is a limit of the representation worth stating.

06 · Problems found

What blocks reproduction today

Blocker

run_search.py cannot start three of the six searches

The launcher creates the run directory to write portable_config.yaml, then the H-sublattice HEAT driver and both conventional fixed-scaffold drivers abort with “Output directory exists”. heat edge and heat wse2 get past this point. Fix: write the YAML next to the run directory (proposed patch in verification/proposed_fixes.patch).
Blocker

Conventional WSe2 config is read as a string

transform_epsilon: 1e-06 in discrete_09.30.26_wse2.yaml is a string under PyYAML (YAML 1.1 needs a decimal point), so config validation crashes. This breaks run_search.py conventional wse2 and the driver’s own unit tests. The source snapshot in baseline_ptycho_guided_320/source/ has the working 1.0e-06; the launcher’s json.dumps re-introduces the problem for any such float.
Robustness

A failed worker hangs the search instead of stopping it

When a worker raises (for us: CUDA out of memory on a 20 GB GPU while relaxing an edge crossover child, whose superposition roughly doubles the active sites), the main process leaves the generation loop and its finally: stop_ga_workers joins workers that are blocked writing results into a queue nobody drains. The job sat idle for 8 h with the traceback hidden; killing the workers surfaced it. Draining or terminating workers in the finally block would make failures visible. Separately, plan for more than 20 GB of GPU memory per worker for the edge case (the archive used larger consumer GPUs).
Text fix

H-sublattice: one sentence reports a per-atom gap as per-H

The conventional-GA gap at generation 20 in the body text is the logged per-atom value relabelled as per H. Fig. 2b itself is correct.
Where
Results, “Sublattice prediction” (page 4), the paragraph that begins “Figure 2b compares the cumulative best formation energies through generation 20”.
Wrong text
…whereas the conventional GA remains 0.012 eV per H atom (2.9 eV total per primitive periodic cell of Mg(BH4)2) above it at generation 20.
Replace with
…whereas the conventional GA remains 0.016 eV per H atom (3.9 eV total per primitive periodic cell of Mg(BH4)2) above it at generation 20.
Why
The drivers log formation energy per atom of the whole 330-atom cell (30 Mg + 60 B + 240 H). The logged gap is 0.01183 eV/atom. Candidate and reference both contain 240 H in the same cell, so the gap is 0.01183 × 330 = 3.90 eV in total, or 3.90 / 240 = 0.0163 eV per H. The text rounded the per-atom 0.0118 to 0.012, called it per H, and multiplied by 240 to get 2.9 eV. Both numbers are low by 330/240 = 1.375.
Leave as is
Fig. 2b’s y-axis label “Ebest − Eref (eV/H atom)”, its caption (“normalized by the number of H atoms”), the plotted curve (the archived PNG ends near 0.016 at generation 20) and plot_h_sublattice_convergence.py are consistent with each other. The conclusion is unaffected: the conventional GA is further from the reference than the text says.
Framing

The conventional GA does reach the H reference, later

The archived 100-generation run reaches the reference at generation 47 after 170,386 evaluations (3.0 h), about 7× HEAT’s cost. The Results text is correct for the 20-generation window. The Discussion’s “fails to reach them over a longer search” fits the edge case but not H.
Provenance

Elemental references are not pinned

Formation energies use Materials Project structures fetched at run time. W and Se from today’s MP match the archive exactly. Fe does not: the archived edge run used μFe = −8.1741 eV/atom, while today’s mp-13 gives −8.2674. For Mg/B/H, the same relaxed H reference gives Ef = -0.23617 today against the hard-coded −0.22290. Gaps at fixed composition are unaffected, but the absolute values cannot be regenerated. Bundling a reference_energies.json per case, as already done for WSe2, would fix this.
Missing input

One WSe2 unit test needs an unbundled TIFF

test_slice_count_validation_and_30_slice_support reads chia-hao_data/objp_zstack_iter0001_30_slices.tif, which is not in the archive. The other 24 bundled tests pass, apart from the YAML-blocked suite above.
Scope

Single stochastic run per method; structure exports removed

Each comparison is one run per method, as the README says, so the generation counts are single samples. Our reruns add one more sample each. Per-generation XSF exports were removed, so the Pearson-vs-generation curve and the structure renders cannot be regenerated. The final structures that the figures use are still bundled.
Note

Many final relaxations stop at the step cap

46% of HEAT edge members and 13% of HEAT H members end their final FIRE relaxation at 500 steps without reaching fmax = 0.05 eV/Å, and are scored as they are (the conventional logs do not record this). The reference-hitting candidates are converged, so the conclusions stand, but unconverged scores are biased high.

09 · Method

How this was checked

  • All computation ran as Slurm jobs on altas, with at most four jobs at once. CPU-only jobs hid the node’s GPUs. No local GPU was used.
  • The UMA checkpoint was downloaded on the workstation and only the model files were copied to the cluster. The Materials Project key was read at run time on altas to fetch six elemental structures into a credential-free JSON. Neither credential is stored in the repository.
  • The drivers were run unmodified. A sitecustomize shim served the fetched MP structures, because the compute jobs get no MP key. Only the generation count, worker count and GPU IDs were overridden. The conventional WSe2 run used transform_epsilon: 1.0e-06.
  • All scripts, the session log and a proposed patch for the launch bugs are in verification/ on branch claude/verify-repo.
